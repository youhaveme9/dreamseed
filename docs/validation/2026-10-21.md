# Local candidate validation

This record captures local validation before the 0.2.0 release. The checks below did not themselves create a commit, tag, release, or remote deployment. Publication uses separate clean commit checks and platform builds described in the [release procedure](../releasing.md). Existing 0.1.0 release assets remain unchanged.

## Tested environment

Apple M3, macOS 27.2, Apple Clang 21, Python 3.12.1, and Java 21. Both pinned official Java server versions were installed after explicit EULA acceptance. Linux and Python 3.11 remain CI targets but are not claimed newly executed on this host.

## Reproduction

```sh
make build
make venv
DREAMSEED_RUN_MINECRAFT_INTEGRATION=1 make release-candidate
.venv/bin/python scripts/release.py --allow-dirty --output dist/0.2.0-rc2-local-20261021
```

The packaging command refuses a nonempty destination. Rehearsal manifests record a dirty working tree and the actual platform. They are not publication approval. Official tests require installed checksum verified jars and explicit EULA acceptance; the build never accepts the EULA or downloads Minecraft automatically.

The standalone terrain CLI also completed a real export with 25 observed samples, matching all three controls, 25 mesh vertices, and 32 triangles. It wrote JSON, SVG, and OBJ into an explicitly selected empty directory. Exports use temporary state and exclusive file creation rather than rewriting MCP job records or existing output files.

The isolated wheel smoke test intentionally uses a missing official jar and confirms actionable unavailable responses for verifier tools. Separate repository integration tests run the actual official servers. This distinction is preserved instead of treating an unavailable branch as successful world verification.

The last fluid checks use actual fluid predicates rather than block names, require positive and negative controls, and repeat fluid absence inside the final clearance command. Explicitly constructed test columns are labeled synthetic controls, not naturally generated seed fixtures. Water plants, waterlogged blocks, and lava are rejected. Console output is bounded to 4096 queued lines; overflow is an explicit error.

## Actual search and verification

`examples/structure48.json` evaluated 50000 full Java 1.21.3 world seeds, using sampling seed 20261020, cohorts of 256, four workers, plains at origin Y 64, and a village within 500 blocks. It found 3612 matches and retained three ranked predictions. The observed native search took 0.865 seconds on this machine; that single runtime is not a throughput guarantee.

The first result was full signed world seed `-3989987067671208281`. A subsequent real MCP `verify_seed_candidate` confirmed plains at X 0, Y 64, Z 0 and the village start at X 32, Z 0. The start chunk had Java 1.21.3 data version 4082 and 177 serialized village pieces. Both hard requirements were verified, there were no verification failures, and the score remained 93.6.

The official surface probe at the village returned Y 74, no water or lava, and explicit clearance. This is not a building entrance or an all hazards guarantee. The village start is 32 horizontal blocks from the world origin, not the actual world spawn. Village block completeness is not claimed.

## Remaining limits

Bedrock support is not implemented or advertised. The installed Docker client could not connect to its daemon, no compatible VM command was found, and the official Bedrock server does not run directly on this Mac. A compatible runtime and independent adapter validation are required; no VM or external host was started.

Complete block validation is limited to pinned igloo template states. Other structures, entity contents, and omitted template coordinates remain outside that scope. Terrain classifications are experimental sampled rules, not semantic guarantees or objective scenic beauty. Metal filtering is placement only and was slower than CPU in the measured small workload. Public HTTP hosting still needs an operator selected OAuth provider, TLS proxy, and production review.

See the [roadmap](../roadmap.md) for exact milestone status. Research boundaries and unavailable platform validation are not marked complete merely because local packaging passed.
